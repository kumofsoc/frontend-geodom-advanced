# Среда — фронтенд MVP для квартир Красноярска

React + TypeScript клиент для кейса: каталог квартир, карта, фильтры, карточка квартиры с районом и инфраструктурой, отдельный блок будущих проектов, рекомендация с причинами, простая регистрация и личный кабинет владельца.

![Стек](https://img.shields.io/badge/React-19-0878ee) ![Стек](https://img.shields.io/badge/TypeScript-5-0878ee)

## Запуск

```bash
npm install
npm run dev -- --host 127.0.0.1
```

Без `VITE_API_URL` запускается **демонстрационный режим**. Он содержит примерные квартиры, иллюстративные фотографии и вымышленные проекты, специально помеченные как демо. Фильтры, регистрация, вход, добавление/редактирование/скрытие объявления и загрузка фотографий работают в браузере. Демо-данные хранятся в `localStorage`, сессия — в `sessionStorage`. Не используйте реальные пароли: клиентское демо-хеширование не заменяет серверную аутентификацию.

Для подключения FastAPI:

```bash
cp .env.example .env.local
# VITE_API_URL=http://localhost:8000
npm run dev
```

Настройте CORS backend для origin Vite. После установки `VITE_API_URL` демо-хранилище отключается и все операции идут через `src/lib/api.ts`. Все карточки, признаки, проекты, оценка и причины приходят готовым DTO от backend. Фронтенд не вызывает ML, геокодер, PostgreSQL или object storage напрямую.

## API контракт, ожидаемый клиентом

| Метод | URL | Результат |
| --- | --- | --- |
| GET | `/api/apartments` | `Apartment[]` опубликованных квартир |
| GET | `/api/apartments/:id` | `Apartment` с вложенными `district`, `features`, `development_projects`, `recommendation`, `photos` |
| POST | `/api/auth/register` | `{id, login}`; тело `{login, password}` |
| POST | `/api/auth/login` | `{access_token, user: {id, login}}`; тело `{login, password}` |
| GET | `/api/auth/me` | `{id, login}` |
| GET | `/api/users/me/apartments` | `Apartment[]`, включая скрытые |
| POST | `/api/apartments` | `Apartment`; тело `ListingInput` |
| PATCH | `/api/apartments/:id` | `Apartment`; тело `ListingInput` |
| DELETE | `/api/apartments/:id` | скрывает объявление; `204` |
| POST | `/api/apartments/:id/photos` | `multipart/form-data`, поле `file`, до 10 фото |

`src/types.ts` — точные интерфейсы DTO. В реальном режиме клиент передаёт адрес как строку, сервер геокодирует и сохраняет координаты/район, рассчитывает признаки и возвращает их. `recommendation.score` может быть `null`, а `ml_available: false` и `warning` показывают мягкую деградацию без ML. Future development показывается отдельно и **не включается** в оценку на MVP. Для проекта указываются `source_name`, `source_url`, статус и срок; ссылка на источник отображается, когда она есть.

После создания объявления фото загружаются последовательно. Если загрузка одного файла упала, само объявление может уже существовать — его можно открыть в кабинете и повторить редактирование. Для production лучше добавить endpoint пакетной загрузки/удаления фото и серверный откат либо явную повторную загрузку.

## Проверка

```bash
npm test
npm run build
```

Карта построена на Leaflet и тайлах OpenStreetMap, поэтому тайлы требуют подключения к сети. Иллюстративные изображения включены локально. Демо-координаты приблизительны; реальные координаты должен выдавать backend.

## Структура

- `src/pages/Catalog.tsx` — аналитический главный экран, карта, фильтры, квартиры.
- `src/pages/Detail.tsx` — готовый DTO квартиры, инфраструктура, будущие объекты, оценка.
- `src/pages/Auth.tsx`, `Account.tsx`, `ListingForm.tsx` — пользовательский сценарий.
- `src/components/MapPanel.tsx` — только визуализация координат и переходы; не считает геопризнаки.
- `src/lib/api.ts` — единая точка подключения backend и интерактивное демо.
- `src/data/demo.ts` — явно вымышленные данные для демонстрации интерфейса.

В MVP нет ипотеки, аренды, чата, платежей и отдельной админ-панели: это вне исходного ТЗ.
